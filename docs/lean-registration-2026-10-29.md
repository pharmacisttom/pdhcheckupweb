# ลดคำถามซ้ำในแบบลงทะเบียน — 29 ตุลาคม 2569

ตรวจนิยามแบบประเมินที่อนุมัติล่าสุดในฐาน local (version 1) กับแบบฟอร์มจริง พบการขอข้อมูลซ้ำระหว่าง canonical intake และ questionnaire ได้แก่ medication_details, allergy, other และ family รวมทั้งตัวเลือกผ่าตัด/โรคที่ปรากฏอีกครั้งในแบบประเมิน

## สิ่งที่เปลี่ยน

- กรอกรายละเอียดยา/อาหารเสริม ประวัติแพ้ และประวัติเจ็บป่วยครั้งเดียว โดยใช้คำตอบเดียวกันในฟิลด์แบบประเมินเดิม กรณีนิยามคำถามตรงกับรายการที่ตรวจสอบแล้วและไม่มี rule/showIf อื่นอ้างอิงคำตอบนั้น
- ประวัติ NCD ญาติใช้ความสัมพันธ์และโรคที่ผู้ใช้เลือกโดยตรงเพื่อเติมคำตอบ family เฉพาะเมื่อข้อมูลแทนกันได้ครบ เช่น เบาหวาน/ความดัน/หัวใจ ไม่มี หรือไม่ทราบ ถ้ามีโรคที่ตัวเลือกแบบประเมินเดิมรองรับไม่ครบ จะคงคำถามเดิมไว้ ไม่แปลงเป็นไม่มี
- ย้ายประวัติผ่าตัดมาอยู่ในกลุ่มประวัติสุขภาพ เอาตัวเลือกผ่าตัดที่ซ้ำออกจากรายการใหม่ในประวัติเจ็บป่วย
- เมื่อมีคำถามวินิจฉัยที่นิยามตรงกัน ให้ตอบคำถามวินิจฉัยโดยตรงเพียงจุดเดียว เอา checkbox โรคเดียวกันออกจากตัวเลือกประวัติอื่น และเปลี่ยนหัวข้อเป็นประวัติการเจ็บป่วยอื่น/รายละเอียดเพิ่มเติม ข้อมูลเก่าที่เลือก checkbox ไว้ยังแสดงและเก็บได้
- ย้ายรายการญาติไปอยู่ต่อจากคำถามครอบครัว ลดการเลื่อนไปมาระหว่างแบบประเมินกับข้อมูลญาติ รายละเอียดครอบครัวเพิ่มเติมเป็นส่วนเปิดขยาย optional และเปิดเมื่อมีข้อมูลเดิม
- คงคำถามเรื่องยาประจำไว้ เพราะแยกจากอาหารเสริม/ยาที่ใช้เป็นครั้งคราว คงคำถามวินิจฉัย ตั้งครรภ์ อาการ และกฎที่อนุมัติทั้งหมด ไม่มีการสร้างเกณฑ์คลินิกหรือสรุปโรคจากข้อความ
- ห้าภาษายังคงข้อมูลเมื่อเปลี่ยนภาษา คำแปลสุขภาพใหม่ยังต้องตรวจทานโดยผู้เชี่ยวชาญ

## API และแบบร่างเดิม

GET questionnaire ส่ง intakeReuse ซึ่งคำนวณจากนิยามและกฎจริง POST registrations รับ reuseIntakeAnswers แบบ optional แล้วคำนวณค่าจาก person ซ้ำฝั่ง server ก่อน validateAnswers และ evaluateRules ไม่เชื่อการจับคู่ที่ client ส่งมา ถ้านิยาม/กฎเปลี่ยนจนใช้ร่วมกันไม่ได้จะตอบ 422 ให้โหลดใหม่

การใช้ร่วมกันเป็นการคัดลอกข้อมูลที่ผู้ใช้แจ้งไปยัง key เดิม ไม่เปลี่ยนชนิดคำตอบหรือกฎ แบบประเมินแพ้ยาเดิมได้รับข้อความประวัติแพ้ทั้งหมดที่ผู้ใช้ระบุใน intake จึงอาจรวมอาหาร/สารอื่น ต้องอ่านร่วมกับหัวข้อ intake; binding นี้จะไม่ใช้ทันทีหากมี rule หรือ showIf อ้างอิง key ดังกล่าว

ถ้าข้อความเกินขีดจำกัด 1,000 ตัวอักษรของ assessment จะยังแสดงช่องเดิม ไม่ตัดข้อความ แบบร่างเก่าที่คำตอบคนละชุดต่างกันจะยังแสดงช่องแยกและรักษาค่าทั้งสองไว้ Client เก่าที่ไม่ส่ง reuseIntakeAnswers ยังทำงานเหมือนเดิม

ข้อมูลเข้ารหัสและ session ownership ใช้ระบบเดิม ไม่มี SQL migration ไม่มี external translation ไม่มีข้อมูลสุขภาพเพิ่มใน URL/log/localStorage OTP ยัง disabled ไม่มีการ deploy/แก้ฐาน production/commit/push ในรอบนี้
